# MemoryEC

唯一实验入口为 `main.py`。`train.py` 保留为底层训练实现，`test.py` 保留旧
checkpoint/预测文件的兼容评价工具。原 `cross_network_cv.py` 和
`sparse_pair_experiment.py` 已合并删除。模型文件、处理后数据与既有输出不变。

## 快速运行

以下命令从项目根目录运行；请使用安装了 PyTorch 的 Python 环境。

```bash
# 默认：Pair Memory，九折，每折独立训练一次（seed=42）
python -u MemoryEC/main.py

# 只运行第9折：Test=Network9，Validation=Network1/2
python -u MemoryEC/main.py --fold 9

# 比较 No Memory / Global Memory / Pair Memory，九折各一次
python -u MemoryEC/main.py --mode ablation

# 三模型九折，每折20次独立初始化（共9×3×20=540次训练）
python -u MemoryEC/main.py --mode ablation --repeats 20

# 仅Pair Memory，第9折20次独立训练
python -u MemoryEC/main.py --fold 9 --repeats 20

# Pair Memory固定稀疏系数，仍以验证集选择阈值
python -u MemoryEC/main.py --sparse_lambda 0.005

# Pair Memory对比固定λ网格（0、0.005、0.02），每折用验证集选择λ
python -u MemoryEC/main.py --mode sparse

# 重新打印默认命名实验的已完成结果：不训练、不推理
python MemoryEC/main.py --mode evaluate

# 读取历史cross_network_cv结果，重建并验证FP/FN和边数，不训练
python MemoryEC/main.py --mode diagnose
```

程序固定使用 GPU；如果 CUDA 不可用会直接报错。训练开始时控制台会打印实际使用的
逻辑 GPU 编号、GPU 名称和显存容量。
`--mode train` 为默认，使用 `--model-type st_pair_memory`（默认）；也支持另外两种模型。
`--mode ablation` 忽略单个 model-type，固定比较 No Memory、Global Memory 和 Pair Memory。
`--mode sparse` 只支持 Pair Memory，固定上述三种 λ，不能同时传非零 sparse_lambda。
普通训练模式下可以直接使用 `--sparse_lambda` 自行调节稀疏惩罚系数，例如：

```bash
python -u MemoryEC/main.py --model-type st_pair_memory --sparse_lambda 0.005
python -u MemoryEC/main.py --model-type st_pair_memory --sparse_lambda 0.02
```

## 参数与训练次数

```bash
python -u MemoryEC/main.py --mode train --model-type st_pair_memory \
  --fold 1 --repeats 1 --hidden-dim 32 --memory-slots 8 \
  --attention-heads 2 --dropout 0.2 --learning-rate 0.0003 \
  --weight-decay 0.001 --batch-size 8 --epochs 150 --patience 15 \
  --sparse_lambda 0 --seed 42
```

`--fold k` 是测试基础网络编号，不是选择某个仿真变体。省略则运行全部九折：
Test=k，Validation=k+1/k+2（超过9循环），其余六家族 Train。同家族所有变体
整体分配；数据直接读取 `data/processed/`，不会重新预处理或改写 `splits.json`。

`--repeats` 只允许 1 或 20。重复编号r从1开始，seed=`base_seed+r-1`，默认
20次对应42..61。每次都重新构造模型和优化器，从头训练；不会接着上一次权重
继续，也不会只对同一权重重复测试。同一重复、不同模型和 λ 使用同一个 seed
便于配对比较。九折划分不随 seed 改变。

FSTA官方参考代码 `train_FSTA_sanch_multi.py` 在20次循环内重建模型与优化器。
本实现借用这一独立重训练原则，但显式记录seed序列，且维持本项目的跨家族
Train/Validation/Test协议，并非照搬FSTA的训练集或测试阈值选择。

## 评价和稀疏项

- 主 checkpoint 固定为最小未加惩罚的验证 BCE（`best.pt`），early stopping 也
  使用验证 BCE；不根据测试结果切换到 `best_val_auprc.pt`。
- 先对每场景全部被试的 sigmoid 概率求平均，再在非对角线评价有向边。
- 主阈值在验证集0.05..0.95、步长0.01搜索：家族内先平均各场景F1，再对两家族
  等权平均。并列取较低阈值，验证阈值保存后才预测测试数据。
- 固定0.5和FSTA自适应阈值只作对比；`--fsta-ratio`（也可写 `--fsta_ratio`）
  设置比例，默认0.5，范围[0,1]。阈值为非对角线概率的
  `min + ratio * (max - min)`。ratio越大，阈值越高，预测边数不会增加。
  只能用训练/验证数据选择ratio，不能根据测试结果调参后声称是无偏测试成绩。
  AUPRC/AUROC始终从连续概率计算，不受ratio影响。非默认ratio使用独立输出目录。

  ```bash
  python -u MemoryEC/main.py --model-type st_pair_memory --fold 9 --repeats 1 --fsta-ratio 0.6
  ```
- 稀疏项仅在训练阶段加入：`BCE + λ * sigmoid(logits_offdiag).mean()`。
  λ默认0，零分支保持原BCE计算；`pos_weight=None`，等效正类权重1。
  不直接惩罚Memory Key/Value或Spatial Attention权重。
- `sparse`模式所有候选训练和验证完成后，用验证家族宏平均F1选择λ；同分取
  较小λ。锁定λ和阈值后才测试。表中`validation_selected_lambda`是这一选择
  程序的结果，各`lambda=...`列只作探索性对比，不能根据Test F1事后选主λ。
  因为既有测试结果已被观察过，稀疏实验仍需标为探索性后续研究，而非全新确认性测试。

## 保存与覆盖

```text
outputs/<auto-generated-experiment-name>/
  config.json
  repeat_01/fold_01/st_pair_memory/
    ...训练权重、日志、validation_selection.json、results.json
```

稀疏网格的三个候选权重放在模型目录下的 `lambda_0/`、`lambda_0.005/`、
`lambda_0.02/`。只保存checkpoint和指标，不再逐被试生成大量预测NPZ。
`config.json`记录九折场景、seed序列、模型参数和评价协议；`split.json`记录
每次每折的家族分配。每次运行训练命令都会从头初始化模型，不再跳过已有结果。
相同配置下，覆盖本次指定折的全部重复、权重、日志和结果，保留其他已完成折；
省略`--fold`时覆盖全部九折。已有实验目录的配置不匹配时，清空该实验目录后重新训练，
避免不同配置的结果混用。汇总表重新生成，不自动备份旧文件；需要保留的实验请先自行备份。
`evaluate`和`diagnose`不执行训练覆盖；历史诊断路径固定为`outputs/cross_network_cv/`，
不再提供`--diagnostics-dir`参数。CUDA可用性检查成功后才开始覆盖训练目录。

## 控制台与结果表

训练进度在第1个epoch结束后输出一行，此后每10个epoch输出（1、10、20、30……）；
早停和训练结束各输出简短信息，不打印模型参数行或包含checkpoint路径的大字典。
Spatial Attention使用数学SDP后端和严格确定性，不再通过过滤警告掩盖非确定性算子。
完整逐epoch记录和训练汇总仍保存为JSON。

运行完成自动汇总所有已完成的折；部分九折完成时明确显示已完成家族集合。
只有某折的全部选定模型和重复均完成才纳入比较，避免模型间不等样本数。

- `scene_results.csv`：每次/每折/每模型或λ/每方法的场景级指标、阈值、最佳Epoch。
- `family_results.csv`：每次训练的测试家族场景宏平均。
- `network_results.csv`：每个网络/方法/模型的重复均值和重复标准差。
- `network_table.csv`：每网络一行的横向对比宽表。
- `summary.json`：完成状态、重复次数和主评价协议。

控制台只打印 Precision、Recall、F1、Accuracy、SHD 五项指标；20次重复时以
`均值 +/- 标准差` 显示，均保留两位小数。概率指标保持0..1量纲，不自动转百分比。
完整的 AUPRC、AUROC、FP、FN、预测边数、真实边数仍写入CSV/JSON，不截断精度。
每家族的边数是场景均值，不是被试总边数。

- Network行：重复实验均值 ± 重复标准差；单次则仅一个数。
Network行中的重复标准差使用总体SD（ddof=0），用于比较同一网络在不同初始化下的稳定性。

## 严格确定性与Spatial Attention

随机种子覆盖Python、NumPy、Torch及所有CUDA设备；cuDNN设置
`benchmark=False`、`deterministic=True`。进一步启用
`torch.use_deterministic_algorithms(True, warn_only=False)`：无确定性实现的算子
应直接报错，不再忽略警告继续训练。默认CUBLAS工作空间为`:4096:8`，必须在CUDA
上下文初始化前设置；若外部传入不兼容的配置则明确报错。

Spatial Attention仍对`[B*T,N,H]`沿ROI轴运行同一个`nn.MultiheadAttention`，
Query/Key/Value投影、softmax、dropout、残差和归一化均未变。仅用
`sdpa_kernel(SDPBackend.MATH)`选择执行后端，禁用flash/efficient/cuDNN SDP和
MultiheadAttention推理fastpath，避免训练或推理绕过数学路径。返回attention权重
时PyTorch可能采用显式矩阵运算分支，同样受严格确定性约束。
没有改Memory检索、Key/Value、输出Gate或Decoder。

`PYTHONHASHSEED`在程序运行时设置不会改变已经启动的解释器哈希行为；需要控制
该项时在启动前显式指定，例如：

```bash
PYTHONHASHSEED=42 CUBLAS_WORKSPACE_CONFIG=:4096:8 python -u MemoryEC/main.py \
  --model-type st_pair_memory --fold 9 --seed 42
```

实验config新增`runtime=strict_deterministic_math_sdp_v1`，旧非严格实验不应直接复用。
数学等价不代表与旧后端逐位相同，也不保证跨PyTorch版本、硬件或
CPU/GPU之间一致。数学路径的速度和内存开销需要在目标GPU上测量。

2026-11-05的小规模验证记录位于
`outputs/determinism_math_check_20261105/verification_report.json`：seed=42、原Pair
Memory、5个epoch、每场景前4名被试、原500时间点，训练52名/验证8名被试，
两个独立进程分别从头训练。CPU上逐epoch Loss、验证选中checkpoint的28个state
tensor、测试输入logits和概率全部逐位一致。旧配置CPU对照同样一致，不能据此声称
新配置才具有CPU可重复性。profiler确认数学SDP前向，反向无严格确定性错误。
CPU旧配置均耗时约2.02秒、新配置约2.06秒（包含训练/验证及checkpoint I/O，
不含曲线绘制）；此样本太小，不作显著速度差异结论。
GPU可用性检查成功，但GPU训练提权请求被环境策略拒绝，故CUDA前后向的一致性、
警告是否消失和GPU速度尚未实测；CPU结果不能替代GPU验证。
